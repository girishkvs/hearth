# Security

For a potential vulnerability, email **girish.sai1@gmail.com** with the affected
version, impact and a minimal reproduction. Do not include passwords, private web
tokens or unrelated personal data. Do not post an exploitable issue publicly
before the maintainer can assess it. No response-time guarantee is implied.

Use email unless the repository explicitly offers GitHub private vulnerability
reporting; do not assume that feature is enabled.

Hearth's privileged boundary is intentionally narrow: approved code identities,
battery/adapter System/Display timeout values, bounded requests and protected ownership.
Normal controls do not elevate. Report any path that bypasses those restrictions.
Lock adds an app-only authenticated publisher and same-user endpoint lookup to the
helper; the helper never executes saver preferences or Apple Events. Final user
connections independently authenticate both peers. Only the native app executes the
fixed current-user/current-host `com.apple.screensaver/idleTime` preference operation.
No component requests Automation consent or needs an Apple Events entitlement.
Original typed presence, fallback/default context and uncertainty are retained.
Writes that would change unrelated inherited screen-saver values are refused.
Password requirements, their grace delay, manual locking, managed policy and automatic
logout are outside the write scope. Configuration readback is not proof of immediate
macOS runtime adoption or restoration; legacy uncertain Apple Event transactions are
not cleared or reinterpreted as confirmed preference writes.
Unsigned local packages do not authenticate a publisher; checksum integrity is
not notarization or signing trust.

Do not weaken macOS security policy, disable password protection, fabricate
receipts, or run destructive/live power experiments while preparing a report.
