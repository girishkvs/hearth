# Hearth 1.0.0

Hearth controls macOS **system idle sleep** through a menu-bar app, Terminal, or
an optional local web page. It does **not** keep the display on or prevent screen
locking. Display and lock controls are deferred.

## Included

- Battery/adapter/Both controls with saved, per-profile restoration.
- Explicit timeouts, truthful current status, and safe handling of interrupted or partial requests.
- A root-owned, exact-code-identity-pinned helper. Normal actions do not prompt for administrator approval.
- GUI and Terminal installation/update/removal using the same native Installer packages.
- MIT license, documentation screenshots using sample data, CI, and a version-gated release pipeline.

## Artifact status

This is a **source-first release**. Packages labeled `local` are unsigned,
ad-hoc-code-signed local builds: **not notarized and not publisher-authenticated**.
Build from source you trust; do not weaken Gatekeeper or SIP if a downloaded
package is refused. Use `docs/installation.md` in the source archive.

Only the architecture in the artifact filename is included. There is no universal
binary claim. `SHA256SUMS.txt` checks download integrity, not publisher identity.
`BUILD-INFO.txt` records the source commit, architecture, toolchain, OS and build epoch.
Machine-specific repair approvals and private web URLs are not release assets.

## Validation boundary

The implementation baseline was exercised locally on Apple silicon, macOS 26.5.1,
Xcode 26.6 / Swift 6.3.3. Fake/isolated tests cover state, authenticated IPC,
native/web controls and installer filesystem behavior. An explicitly approved
installed-helper battery1 → 0 → 1 cycle completed without per-action prompts,
with all other settings restored unchanged.

CI is configured for macOS 15 with Xcode 26.3; its hosted result must be checked
after publication. macOS 13 is the deployment minimum, not a claim that every
OS/Intel combination was live-tested. Physical battery idle behavior and reboot
persistence have not been exhaustively exercised.

Authorized GUI and direct-TTY updates of the native-architecture package completed.
The direct Terminal run captured exit 0 and the user confirmed return to the shell
prompt. Each route preserved full settings/active restore state and verified the
complete installed 1.0.0 inventory, signatures and helper readiness.

The subsequent compact progress display and first-launch guidance have replay
and resource coverage, not a further live install. Replays are labeled as such.
See `docs/releasing.md` for the evidence boundary, including the earlier test
launcher whose final exit was not captured.

Legacy private builds used `2.0.*` build labels. Public1.0.0 is a product release
version, not an IPC/state schema reset. Maintenance preserves verified state and
requires explicit consent to enroll rebuilt code.
