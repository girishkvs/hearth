# Hearth 1.2.0 - 2026-09-12

Hearth 1.2.0 adds independent Display control and coordinated Lock settings through public
current-user CFPreferences, without Automation setup.

## Installed-product acceptance

On September 9, 2026, candidate `4ff5f1a` (build `1.2.0.20260909074248`) completed
a real GUI update on Apple silicon/macOS 26.6.2. The installed inventory,
signatures, code pins and empty app entitlements matched the reviewed package.

presence/context were unchanged. One ordinary status call migrated to schema 4
without inventing Display or Lock ownership.

The actual installed CLI-to-broker-to-native path then completed **LockOn followed
by RestoreLock**, both exit 0, in **3.5848 seconds**. The timer changed from absent
to integer zero and back to exact absence. Only Display's 2/10-minute values were
acquired and restored; pre-existing System zero values, including the battery
original-1 restore record, remained borrowed. Full power output and raw schema-4
ownership matched the pre-cycle baseline, the Lock record was released, and

This proves that candidate's installation, migration and product configuration/
restoration path. Later source or package builds identify their own commit and

Production status never parses fragile OS logs to claim runtime protection.

## Included

- Native menu and local web page show short actual System/Display/Lock state and
  separate actions, with target/timeout details under Advanced.
- CLI power commands accept `--setting system|display`. The default remains System;
  `hearth on` does not disable display idle sleep or change locking.
- `pmset displaysleep` uses only the selected battery/adapter profiles, with
  independent restore ownership, idempotency, read-back and interruption recovery.
- `hearth lock on|restore|status` controls current-user idle triggers through the
  native app. One Restore Lock releases only acquired values; existing awake
  settings and pre-existing System0/original1 restore ownership remain borrowed.
- System/Display dependencies are disclosed before Lock activation and identified
  as Required by Lock afterward, with a direct single restore action.
- No Automation setup, Apple Events sender or prompting path. CLI/web retain the
  authenticated app-only per-user XPC service: one serialized current-user writer,
  not a new root preference service. The helper routes authenticated endpoints only.
- State schema 4 migrates valid 1.0.0 System and unpublished schema 2/3 records without inventing display
  baselines. An active battery System original 1/applied 0 is retained when actual
  remains 0. Mixed IPC versions require a matching explicit update.
- Existing GUI/CLI setup, update/removal, compact real-progress output, verbose
  mode, exit handling, source-build and CI contracts remain in place.

## Lock scope and limits

The public backend writes only current-user/current-host `idleTime`, using
`CFPreferencesSetValue` and exact-tuple synchronization. It captures the exact
typed integer or absence. Effective values follow the first nonempty engine
dictionary: current-user/current-host, current-user/any-host, then any-user/any-host.
Missing keys fall back to Apple's installed `EngineDefaults.plist` resource,
not a hardcoded 1200 or a guessed zero. Context fingerprints guard the captured
fallback/security context; writes that would shadow unrelated fallback or security
values are refused. Missing or invalid context disables the action.

**Configured** means settings were saved and read back, not proof of immediate
macOS runtime adoption. **macOS may adopt or restore the timer later.** Restoring
an absent timer removes it instead of storing the effective default. No private
lifecycle calls, profile writes, fake activity or production log parser is used.

The conservative policy gate requires verified system-wide absence of profiles
and enrollment, local-only directory scope, no relevant or unknown user/node policies, no MCX,
no forced saver preference and no automatic logout. Managed or unknown policy
evidence disables the feature rather than guessing missing restrictions.
Nil/no-error public OD results retain explicit absence provenance; inherited node
policies remain checked. A strict single-expression password-content-only rule may
be retained without treating it as an idle timer. No policy is modified or evaluated.

Password requirements and exact grace delay, deliberate locking, logout and system
safety are outside the write scope. There is no fake activity, private policy bypass,
auto-unlock or unlocked-screen-off mode. The completed local acceptance does not
cover the broader OS/hardware/managed-policy matrix, reboot behavior, power-source
switching or a sustained physical-idle test of the installed product.

A successful reply and typed configuration readback are required to report
Configured. Legacy Apple Events pending transactions remain quarantined; matching
readback, elapsed time or PID disappearance cannot clear them. Confirmed legacy
timer acquisitions without a preference-presence baseline remain recovery-only,
not rewritten as CF records. No automatic replay or recovery of uncertain legacy
writes is claimed. A context-only mismatch while Hearth's stored timer remains
zero also retains the journal and dependencies with restoration disabled; it does
not count as release or authorize another write. Settings persist across exit/
crash, and the journal must be retained for explicit recovery.

Separate setting ownership does not guarantee independent physical macOS effects:
display and system idle policy can interact. Display-always-on is not a promise to
prevent every lock, lid-close sleep, critical-battery or other safety action.

## Updating and validation boundary

Read [migration](../migration.md) before an update. Building or refreshing release
artifacts does not replace an existing installation or change its live state.
Further installation or physical tests still require explicit approval.
Use Restore Lock and the remaining System/Display Restore actions, or native
Restore and quit, before removal if restoration is desired. Older clients cannot
interpret schema 4; no automatic downgrade conversion is provided.

Coverage uses isolated fake power/saver/state, actual anonymous XPC transport with
fake controllers, protocol/worker tests, native smoke and
WebKit UI/resource previews, and package inspection without installation.
README and usage images show the actual primary menu with isolated sample data.
Advanced-panel and web/resource captures are labeled separately; a secondary
panel is not a primary-menu capture. The two primary-menu images capture the
real `NSMenu` popup's own view in an active GUI session with bounded sample-app
activation. No input is synthesized, no capture permission is requested, and the
installed runtime is not used. Images are not personal desktop captures or
evidence of a live settings change.
These isolated checks supplement, rather than replace, the installed-product
acceptance above. They do not establish the untested physical-idle, power-switching,
reboot or broader password/MDM behavior.

`VERSION` is exactly `1.2.0`. Local setup/removal artifacts remain unsigned,
ad-hoc-signed-code distributions, not Developer ID/notarized or
publisher-authenticated packages.
